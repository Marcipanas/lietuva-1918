# Lietuva 1918 — guide for AI coding agents

A 3D economy and city builder of Lithuania from 16 February 1918, in the spirit of Workers & Resources. The world has **no grid**: roads and railways are free curves, buildings sit at any angle. Plain JavaScript, three.js for the view, **no build step**. It runs from any static host, offline as a PWA, and as a claude.ai artifact.

Read this file first. Details live in `docs/`:
- `docs/ARCHITECTURE.md`: modules, data structures, units, tick order, the 3D view, performance budget
- `docs/GAME_DESIGN.md`: every mechanic and number
- `docs/ROADMAP.md`: planned features with specs
- `docs/DECISIONS.md`: why things are the way they are

## Commands

| Command | What it does |
|---|---|
| `npm test` | Static checks plus a headless smoke test: loads every script in a stub DOM (three.js runs for real; only WebGL is stubbed), plays about two in-game years through the real tools, trades through a border post, walks history through its borders and key decisions (Vilnius in 1919 and 1920, Żeligowski both ways, the Hymans union, the litas, 1923, 1934, 1939, 1940, 1945, 1947), renders every panel and zoom level, saves and reloads. **Must pass before every commit.** |
| `npm run serve` | Local server on http://localhost:8080. The service worker needs http, not `file://`. |
| `npm run world` | Rebuilds `js/world1918.js`, the 1918 start map with its terrain raster packed (about 18 s). Needed after changing `common`, `data`, `geo`, `land`, `geom`, `terrain` or `world`; `npm test` fails until you do. |
| `npm run geo` | Rewrites `js/geo.js` from `tools/geo/geo.json`, `places.json` and `regions.json`. Rebuilding those from the sources needs downloads and shapely (`tools/geo/README.md`). |
| `npm run build:artifact` | Writes `dist/artifact.html` for publishing as a claude.ai artifact. |
| `npm run icons` | Regenerates the PWA icons (needs Python Pillow). |

There is nothing to install. Node 18+ for the tools, any browser with WebGL to play.

## Ground rules

1. **No bundlers and no npm packages.** The one library is three.js r159, vendored as `vendor/three.min.js` (the last version with a classic-script build). Do not add others without a decision in `docs/DECISIONS.md`.
2. **All scripts share one global scope.** A top-level `const`/`let`/`class`/`function` name may exist in only one file. A duplicate is a SyntaxError that silently stops the later file in a browser. `tools/check.js` parses all scripts together to catch it. Watch for names already taken by the data: `GEO_LT`, `GEO_C`, `GEO_SEA`, `GEO_LAG`, `GEO_BORD`, `GEO_KR`, `GEO_KRW`, `GEO_PAL`, `GEO_V39`, `GEO_V40`, `GEO_EP`, `GEO_RIV`, `GEO_LAKES`, `PLACES` (geo.js), `REGIONS`, `OWNERS`, `OWN_GATE` (data.js), `LAKES`, `FOR`, `FIELDS`, `BOGS`, `CLAYS`, `FLAXR`, `MAP_LBL`, `CITY_PLAN`, `LANDMARKS`, `RAIL1918`, `ROAD1918`, `BORDER_ROADS` (land.js), `WORLD1918`, `FOOD`, `FOODS`, `MARKETS`, `CARDS`, `HEV`. Old names like `SEA` and `FIELDS` have caused this bug.
3. **Units are km.** `x` east, `z` south, `y` up. The country is drawn `MAPK` = 2 times its real size (docs/DECISIONS.md 38): distances between places are doubled, towns keep their drawn size (about five times larger than life; a lot is 0.42 km). Rules that span the country are written in real km and scaled by `MAPK`; rules inside a town are not. The player sees real km: show distances with `kmTxt(x)`. Buildings and lots are rotated boxes `{x, z, rot, w, d}`; local +z is the front, which faces the road. Models are written at twice their size and scaled by `MS` = 0.5.
4. **Simulation code never touches the DOM, the canvas or THREE.** `common`, `data`, `geo`, `geom`, `terrain`, `world`, `sim` and `history` must run headless; the smoke test depends on it. The view reads the world; the world signals changes through `WV` version counters and `terrainHook`.
5. **Saved games:** a new version starts a new game (docs/DECISIONS.md 33). `SAVE_KEY` in `js/data.js` carries the version, so bump it with `package.json` and `VERSION` in `sw.js` (`tools/check.js` fails otherwise); on start `dropOldSaves()` removes older saves. Write no code to read older saves or migrate them. Figures each day recomputes stay out of the save (`DAILY` in sim.js).
6. **Offline cache:** after changing any shipped file, bump `VERSION` in `sw.js`. A new file must also be added to `SHELL` in `sw.js` and to `index.html`; `tools/check.js` fails otherwise.
7. **Performance:** add drawable things as instances in an existing `Pool` (scene.js), give anything numerous a distance limit, and rebuild meshes only when a version counter changes. See the budget in `docs/ARCHITECTURE.md`.
8. **Copy:** plain words, active voice, short sentences, no em-dash asides. Buttons say what happens ("Build", "Remove route"). Distances in km, population in thousands (`popStr`), goods per day.
9. **History:** dates and facts in events and descriptions must be accurate. If only the year is certain, give the event `y: 1` so the Chronicle shows the year alone. Every decision-card option says whether it is what happened, and the one that did carries `h: 1`. Events that only follow a choice history did not make say "This did not happen". Dark events (deportations, the Holocaust) are stated plainly and are never choices. Vilnius changes hands from January 1919 as it did (docs/DECISIONS.md 31), and so does the neighbours' land (32): write no event that the map contradicts.

## Concepts you need before changing code

- **Terrain raster:** cells of `CELL` = 0.5 km hold terrain (`TT`), feature bits (`TF`: forest, fertile, bog, clay, flax, Klaipėda Region, inside Lithuania), today's country (`CTY`) and the part of Lithuania that changed hands (`RGN`). It drives rules and path planning only. Forest clearing goes through `setFlags`, which calls `terrainHook` so the view updates.
- **Who holds the land:** `S.own` maps each part of Lithuania (`kr`, `pal`, `vr`, `vr2`) and each neighbour's land (`lv`, `by`, `pl` the Suwałki region, `ep` Masuria, `ru`) to its holder (`lt`, `lv`, `pl`, `de`, `al`, `ra` the Red Army of 1919 and 1920, `by`, `ru`). At the start German troops hold all the neighbours' land. Change it only with `setOwner(key, holder)`, which locks or unlocks the towns there, splits lines at region lines, drops deals and moves the capital. `heldOff(k)` / `heldOffAt(x, z)`: land of today's Lithuania others hold, where nothing is built or planned; `e.off` marks lines there, which every network sweep skips. The view repaints when `WV.own` changes.
- **The graph:** `S.nodes` and `S.edges` (`{id, k: 'road'|'rail', lv, a, b, p}`); runtime lookups `NODES`, `EDGES` and the spatial hash `EH`. Always change it through `buildLine`, `splitEdge`, `removeEdge` or `applyBull`, which keep indexes and `WV.net` right.
- **Settlements:** `S.towns` holds towns and villages (`t.vil`), all at their real places. Each feeds and heats its 1918 population `t.pop0` from its own land, so it keeps its size without help; growth needs food, homes and jobs. `t.rg` is its part of Lithuania (set on load, not saved) and `t.lock` follows its holder. `t.capital` marks the capital: Vilnius, or Kaunas while others hold Vilnius or while the government sits there (`S.hist.kaunas`, from January 1919 until `seatVilnius()`); see `capital()`, `fixCapital` (`t.cap` is storage capacity). Text that names the capital uses `capital().n`.
- **The start map** is `genWorld()` run once by `tools/build-world.js` and stored in `js/world1918.js`; `newGame()` loads it. Geography comes from `tools/geo` (generated `geo.js`) and `land.js` (hand-drawn). The neighbours' land is in the raster as `CTY` codes (today's Poland split on the old border of East Prussia: `pl` and `ep`): `borderOf(x, z)` gives a border post its market from them.
- **Landmarks:** buildings with `b.lm` (a key of `LANDMARKS`) and a footprint of their own (`b.fp`); Vilnius and Kaunas town halls are landmarks. They cost nothing and cannot be removed.
- **Network:** `analyze()` gives every road point an owner by road distance (two multi-source Dijkstra sweeps from the halls: plain for homes, with a 6 km head start against villages for workplaces), assigns buildings and lots within `TERRITORY` km, finds neighbours where catchments meet, groups by union-find (`NET.comp`: any road or rail, for routes; `NET.grid`: railways and paved roads only, which is the power grid; `NET.linked`: the capital's grid group, which goals count; `NET.rail`: towns on the capital's railways), line upkeep and pollution sources. Town-to-town paths come from `pairPath(k, a, b)`, computed on demand and cached until `NET.ver` changes. Set `NET.dirty = true` after any change that affects them.
- **Day tick:** phase1 → `routeEval` → `commute` → phase1b → power grid → phase2 → `runRoutes` → `runTraders` → `runDeals` → `develop` → upkeep and `histSpend` (army, allies) → the day's balance (`S.inc`, and `S.bud` by kind from `BUD`) → `histTick` (events, cards, news cards, plan) → random events → ministry tasks. See `tick()` in `js/sim.js`.
- **History:** a decision card in `S.hist.cards` pauses the game (`S.speed = 0`); `pickCard(n)` applies an option and restores the speed. `S.hist.path` is `'free'`, `'soviet'` or `'neutral'`; events check it with `when`, cards with `when2`. Events are kept in `S.ev` by their `id`, so add new ones anywhere in `HEV` with a fresh `id`. An event's `fx` may return a text, such as what changed hands, which is added to its line in the Chronicle. `S.hist.picks` holds the answers; later cards and events read them.
- **Goods move on routes, and slowly with merchants.** Auto cargo equalizes days of supply in one direction only, so goods never ping-pong, and also moves a store's surplus (over 75% full) to a town with room. Private merchants (`runTraders`) carry a little between neighbouring towns (`NET.edges`), from plenty to need, at most `TRADE_CAP` loads a day per link (docs/DECISIONS.md 39); `TRADES` lists the day's flows for the carts on the map. Trade abroad leaves from the stock of a town with a border post or port (deals, which keep a share of the store, `d.lim`), so routes bring goods to the border.
- **Agents are visual only.** Walkers and vehicles show what the aggregated simulation does; they never move goods.
- **Panels:** `renderPanel(false)` rebuilds nothing if the HTML structure is unchanged; it only patches values made with `v(key, text)`, widths made with `w(key, pct)`, chart paths made with `pd(key, d)` and states made with `sc(key, state)` (CSS reads `data-c`). A changing number shown without them makes the structure change; the panel then rebuilds at most every 1.5 s, and a button can miss a tap.
- **Interface layout:** a status bar on top, the map, and a bottom bar with five views (`NAV` in ui.js) that open the sheet: a bottom sheet on phones (`VIEW.sheet` 0 closed, 1 half, 2 full) and a side panel from 960 px. A tool replaces the bottom bar with the action bar (`showBar`). Panels cover the bottom of the view, so the camera's target is drawn in the middle of what stays visible (`VOFF`, `setViewOffset` in scene.js); use `[cam.x, cam.z]` as the centre of the view, not the middle of the canvas.
- **Tools:** one finger always moves the map. A tap acts; hold and drag draws or paints. Lines are lists of points: never build the planner's raw path, which wanders off existing lines on its 0.5 km cells; `routePieces` replaces those stretches with the network's own way and builds only the rest.
- **Dashboards:** the day tick leaves made and used goods per town (`t.mk`, `t.us`) and growth (`t.gr`); dash.js turns these and the usual figures (`fed`, `heat`, `house`, `hint`, `pr`, `pol`, buildings' `why`) into problems. A new kind of problem goes in `townIssues`, with a fix that is an `act` the UI already has (`suggestRoute` brings a good from the neighbour with most to spare, `suggestOutlet` sends a surplus to the one that needs it most).
- **News and cards:** simulation code pushes short texts to `NOTES`, which the interface shows as toasts (never call `toast` from sim or history code). A new game starts paused on the intro card (`S.intro`); a new era opens on its card (`S.eraCard`); history that moves a border or the capital queues a news card (`queueNews`, from events with `news` and `nd`) in `S.hist.news`, which pauses like a decision card; decision cards come from `S.hist.cards`, and an option is marked with a tap (`pickOpt`) and applied with Confirm. `showCard()` picks which one is up.
- **Ministry tasks:** `OBJ` in sim.js, easy to hard, with `ok()` and an optional `can()` (the task makes sense now). The map shows `curTask()` above the bottom bar.

## Recipes

- **Move or add a landmark, a city street, a railway or highway of 1918:** edit `LANDMARKS`, `CITY_PLAN`, `RAIL1918` or `ROAD1918` in `land.js` (lon/lat), add a model `LM_<key>` to `MODEL_FN` as `lm_<key>` for a new landmark, then `npm run world` and check the log for lines it could not build.
- **Change borders, rivers or the list of places:** see `tools/geo/README.md`, then `npm run geo` and `npm run world`.

- **New building:** add it to `BT` in `data.js` (cat, era, `fp: [w, d]` in km, w, in/out, need, cost, pol, d). Add a model function to `MODEL_FN` in `models.js` (front at +z, fit the footprint; optional `smoke`, `fields`, `flag`, `cows`, `pigs`, `boat`). If it needs special ground, extend `validPlace` in `world.js`, `quickNeed` in tools.js (so `findSpot` stays fast) and `NEED_TXT` in panels.js; ground the overlay can light goes in `needKey` (tools.js) and `NEED_BIT` (scene.js). If it makes a good, list it in `PRODUCER` (dash.js) so problems can offer it as a fix. Add an icon to `ICON` if none fits, then place one in `tools/smoke-test.js`.
- **New resource:** `RES` and `RI` in `data.js`, `RCOL` in `agents.js`, CSS variable `--r-<name>` in `css/style.css`, an icon. If it is food, add it to `FOOD`.
- **New historical event:** `HEV` in `history.js` with an exact date (`y: 1` if only the year is known) and `when` for the path it belongs to. An event that moves a border or the capital also gets `news` (a headline) and `nd` (what it means for the player): it then opens a news card instead of a toast. Random events go in `REV` (sim.js).
- **New decision card:** an entry in `CARDS` (history.js) with `t`, `when` (date text), `txt` and `opts` (`t`, `d` saying whether it happened, `h: 1` on what happened, optional `risk: {sec}`, `go(ok)`; `txt` and `d` may be functions), optional `when2`, then an `HEV` entry with a new `id` and `card: 'id'`. Drive it in the smoke test with the `jump()` helper (history only, answering cards as history went unless told otherwise) and `act({act: 'card', o})`; try the other options from a `keep()` snapshot and `back()` to it.
- **A border change:** `setOwner('kr' | 'pal' | 'vr' | 'vr2' | 'lv' | 'by' | 'pl' | 'ep' | 'ru', holder)` in an event's `fx` or a card option, and a line for the Chronicle with what changed hands (`landTxt`; an `fx` can return it). A new holder needs a name in `OWNERS`, a market in `OWN_GATE`, a colour in `OWN_COL`, map words in `OWN_LT` (and `OCC_LT` if it occupies a neighbour), a tag in `OWN_SHORT` and a line in `heldBy`. A new part of Lithuania needs an outline (`tools/geo/build_regions.py`, `npm run geo`, `npm run world`), a code in `RGN_KEY`, an entry in `REGIONS` and `startOwners()`, its fill in `genTerrain`, its outline in `borderPieces`, and a label text in `nlText`.
- **New market or good abroad:** `MARKETS` in history.js (`gate`, `buy`, `sell`) and its opening state in `newMarkets()`.
- **New ministry task:** `OBJ` in `sim.js`.
- **New panel section:** a string function in `panels.js`; route every changing number through `v()`, and changing colours through `sc()`.
- **New problem on the dashboards:** a line in `townIssues` (dash.js): a key, a severity (2 urgent, 1 holds the town back, 0 a note), an icon, a title, a detail and fixes as `{t, a: {act, ...}}`. Add it to `townAlert` if it should colour the town's dot on the map.
- **New overlay:** add it in `buildOverlays` (scene.js) and include whatever it depends on in that function's cache key.

## Testing

`tools/smoke-test.js` is the safety net. When you add a system, drive it through the same functions the UI calls (`setTool`, `tapTool`, `undoStep`, `beginDraw`/`moveDraw`/`finishDraw`, `setGhost`, `findSpot`, `doConfirm`, `navTo`, `act({...})`) with world km coordinates, and assert on `S`. For visuals, run `npm run serve` and check a phone-sized viewport (390×844) in a real browser; headless Chromium can screenshot WebGL with `--use-angle=swiftshader --enable-unsafe-swiftshader`. To test gestures there, dispatch `PointerEvent`s on the canvas (`pointerType: 'touch'`); the handlers tolerate pointers the browser did not start.

## Publishing

- **GitHub Pages:** `.github/workflows/pages.yml` deploys `main` after the tests pass. One-time setup: Settings → Pages → Source: GitHub Actions. On GitHub's free plan Pages needs a public repository, so the deploy job is skipped while the repository is private.
- **claude.ai artifact:** `npm run build:artifact`, then publish `dist/artifact.html` with `css/style.css`, `vendor/three.min.js` and `js/*.js` as supporting files at the same relative paths. Service workers do not run inside artifacts.
